Herdr is a terminal workspace manager. It keeps real terminal processes running and adds structure around them.

## Workspace

A workspace is the top-level project container. Use one workspace per repo, task, or investigation.

A workspace owns tabs and panes. Its sidebar state rolls up from the agents inside it, so you can see which project needs attention.

## Tab

A tab is a layout inside a workspace. Use tabs to separate views like `agents`, `logs`, `server`, or `review`.

Tabs are addressable from the CLI and socket API.

## Pane

A pane is a real terminal. Herdr renders the terminal output, sends input back to the process, and preserves the pane across client detach.

Panes can be split right or down. They can be renamed manually, read from the CLI, sent input, and closed.

## Mouse UI

The expanded sidebar defaults to a project tree. Each workspace contains its agent and shell panes, including panes in other tabs. Click the chevron to collapse a project, the project name to switch workspaces, or a child to focus its terminal. The `+` button creates a terminal in that project. Right-click a project to create a terminal or run a command in a new terminal; right-click a child to rename, split, or close its pane. Commands run through your normal shell, so personal launch commands such as `cdx` or `wb` can be entered directly.

Each terminal has one centered content line with clickable padding above and below. Project headings use brackets and bold green text, with the Git branch alongside when available, children are indented, and ordinary shells use muted text. A manual pane name takes priority; otherwise the agent type is shown, with a stable pane number when the type repeats within a project. Dynamic titles and terminal ID subtitles are omitted. The rightmost status slot shows a bold green rectangular dot-matrix spinner for working, `!` for input needed, a blue dot for unread completion, a green solid dot for idle, or a dim dash for unknown. Only the focused pane is highlighted during normal browsing. Right-click a pane and choose 状态说明 for its full name, project, tab, pane ID, and status meaning. Visible online working indicators animate while the client is focused and no dialog or terminal popup is open. Collapsed projects retain blocked and unread counts, including hidden worktree children. Long names use an ellipsis.

The default sidebar width is 30 columns, with a configurable maximum of 44; narrow windows reserve space for the terminal. The bottom 新建项目 button opens the existing project creation flow. Closing a project's last pane records its current shell-reported directory and derives the automatic name from that same path; the launch directory is the fallback when terminal information is unavailable. This directory is recorded under 最近项目, independently of the session layout. Click a recent project to open a new terminal or focus its existing workspace. This directory history survives server restarts, is isolated by session and machine, and is available only on servers advertising the optional `project.list`, `project.open`, and `project.forget` JSON methods. Right-click to view the full path or forget the record; forgetting does not delete files. Missing directories retain their records and show an error. Closing a project keeps its record visible even when another workspace or an automatic fallback shell uses the same directory. Successfully reopening a recent project removes its record; a failed open keeps it. New closures expand the recent list and reveal its newest record. RGB sidebar and selected backgrounds use subdued neutral tones; text colors are preserved. The recent list shows up to four rows with independent scrolling and collapse; short windows use a compact layout.

In workspace navigation mode (`Ctrl+b`, then `w` by default), `Tab` and `Shift+Tab` traverse visible project and terminal nodes, including ordinary shells. Arrow keys retain workspace preview navigation. Keyboard focus changes expand the destination project and scroll its pane into view. Completion badges retain Herdr's client-specific seen state; expanding the tree does not mark a completion as seen. For the separate workspace and agent panels, set `ui.sidebar_layout = "split"`. Compact and mobile layouts keep their existing behavior.

Herdr is mouse-native. You can click panes, tabs, workspaces, and agents. You can drag split borders, select text, and use right-click menus. Everything below is also reachable by mouse; keyboard bindings are an optional layer.

If you prefer keyboard-only control, or you want Herdr to stop capturing mouse input, disable mouse capture:

```toml
[ui]
mouse_capture = false
```

## Agent

An agent is a process Herdr recognizes inside a pane. Herdr detects agents from foreground processes, screen manifests, and optional integrations.

Agent states are:

| State | Meaning |
| --- | --- |
| `blocked` | The agent needs input, approval, or a decision. |
| `working` | The agent is actively running. |
| `done` | The agent finished and you have not looked at it yet. |
| `idle` | The agent is finished or waiting and has been seen. |
| `unknown` | Herdr cannot confidently classify the state. |

Each client tracks which completions it has displayed. Viewing a completion in one client does not clear another client's Done badge. CLI/API statuses use the server's seen state, so they need not match a particular client's badge; both `idle` and `done` mean ready for input.

## Session

A session is a persistent Herdr server namespace. The default `herdr` command attaches to the default session.

Named sessions are separate runtime namespaces:

```bash
herdr session list
herdr session attach work
herdr session attach side-project
```

Use workspaces first. Use named sessions when you need completely separate panes, sockets, and persisted runtime state.

## Client and server

By default, Herdr runs as a background server plus one or more attached clients.

The server owns panes and process state. The client is the terminal UI attached to that server.

With one attached client, all tabs follow its size as before. With multiple clients, each can view its own workspace and tab. Different viewed tabs follow their respective clients; when clients view the same tab, the last one to focus, select, or interact with it controls that tab's pane sizes.

Detach the client with `ctrl+b q`. The server and agents continue running.

If you want to end the session and stop its panes, stop the server:

```bash
herdr server stop
```

## Modes

Herdr has terminal mode, prefix mode, and navigate mode.

Terminal mode sends keys to the focused pane. Prefix mode waits for one Herdr action after the prefix key. Navigate mode is the persistent workspace navigation surface.

Press the prefix key, default `ctrl+b`, then an action key such as `c` for a new tab or `w` for workspace navigation. See [Keyboard](/docs/keyboard/) if the prefix idea is new to you.
